═══════════════════════════════════════════════════════════════
   INFRANEST (PRISM) - QUICK START
═══════════════════════════════════════════════════════════════

OPTION 1 - EASIEST (Windows):
   1. Double-click: START_ALL.bat
   2. Wait ~10-15 seconds for both servers to come up
   3. Browser opens automatically to http://localhost:5173

OPTION 2 - BACKEND ONLY:
   Double-click: START_BACKEND.bat
   Server: http://localhost:8000

OPTION 3 - MANUAL:
   Terminal 1: cd infranest\core && python server.py
   Terminal 2: cd infranest && npm run dev
   Browser: http://localhost:5173

═══════════════════════════════════════════════════════════════
   VERIFYING IT'S RUNNING
═══════════════════════════════════════════════════════════════

1. Health check:
   curl http://localhost:8000/health
   Expected: {"status": "healthy", ...}

2. Manual integration checks (require the backend running locally -
   these are debug scripts with print output, not an automated/CI
   test suite; see README.md "Testing" for details):
   python test_frontend_integration.py
   python infranest\core\test_api_debug.py

3. Try the UI: open http://localhost:5173, describe a backend project,
   answer the core questions, and generate code for a framework.

═══════════════════════════════════════════════════════════════
   WHAT THIS DOES
═══════════════════════════════════════════════════════════════

1. Natural language -> DSL: describe a backend project in plain
   English; the backend calls Groq (Mixtral) if GROQ_API_KEY is set,
   otherwise falls back to a template-based DSL.
2. Follow-up questions: AI-generated questions to refine the spec
   (falls back to rule-based questions without an API key).
3. DSL editor: review/edit the generated YAML spec before generating
   code.
4. Code generation: Django + DRF, Go Fiber + GORM, or Ruby on Rails
   from the same DSL.
5. Download: a ZIP of the generated project.

See README.md for the full feature list, architecture, and the
"Project Status" notes on what's simulated (deploy_project, view_logs,
run_audit, simulate_api in the copilot CLI - see copilot/README.md).
